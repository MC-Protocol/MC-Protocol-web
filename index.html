Minecraft Protocol Values for Anticrash Development

A single-page reference of every wire-format constant, vanilla-enforced packet limit and known crash vector used when writing server-side validation (anticrash) for Minecraft Java Edition. Built from the Minecraft Wiki wiki.vg merge, the Netty 4 ByteBuf javadoc, PrismarineJS minecraft-data, MCProtocolLib and ViaVersion sources.

⚠ Read this first: numbers marked wire are protocol constants; vanilla are enforced by the vanilla server/client (safe baselines for kicks); version-dep changed between releases — always re-check per protocol version in the links below. These are defensive limits, not guaranteed constants.

Anticrash framing checks

Reject: length VarInt > 3 bytes · length > 0x200000 · DataLength > 0x200000 · zlib output exceeding its declared size · packets arriving before Set Compression · unknown intent ≠ 1/2/3.

Anticrash: when re-serializing client NBT (books, signs, item names), bound depth ≤ 512, total serialized size, list sizes and duplicate keys. Deep recursion = StackOverflow; huge payloads = “book ban”.

Item stacks & slots

Slot format (1.20.5+)

Slot:
  present: Boolean
  if present:
    count:    VarInt          (empty stack on the wire = present=false, i.e. count 0)
    itemId:   VarInt          (registry id — must exist!)
    addedComponents:   VarInt count, then (type VarInt + payload) pairs
    removedComponents: VarInt count, then VarInt ids

Pre-1.20.5: count: Byte (≤0 = air), item: VarInt, nbt: Optional NBT.

Position / Angle / UUID

// Position: 8-byte long, since 1.14 — X:26 | Z:26 | Y:12
long x = v >> 38;             // sign-extended automatically
long y = v << 52 >> 52;       // lowest 12 bits
long z = v << 26 >> 38;       // middle 26 bits

// Angle: 1 byte, 0..255 → 0..360° (step 1.40625)
float degrees = byteValue * (360f / 256f);

// UUID: two big-endian longs (MSB, LSB) — 16 bytes
UUID uuid = new UUID(buf.readLong(), buf.readLong());
Movement packets: vanilla clamps X/Z to ±29,999,984 (±3.0E7) and Y to ±2,031 on the client; the server should reject NaN/Infinity floats (Float.isFinite) and impossible deltas.

Crash & exploit vectors

VarInt too big / overlong 🔴

5+ bytes for length prefix, or 32+ bits set.

length VarInt ≤ 3 bytes; in-packet VarInt ≤ 5 bytes / 32 bits; reject non-canonical (overlong) encodings.

Negative / huge array length 🔴

new byte[negative] → NegativeArraySizeException; new byte[huge] → OOM before reading.

check length ≥ 0 and length ≤ buf.readableBytes() (or a sane cap) before allocating.

Decompression bomb 💣

Tiny packet inflates to gigabytes → OOM/CPU burn.

cap uncompressed size at 2,097,152 like vanilla; cap compressed:uncompressed ratio and total inflate rate per connection.

Book ban 📚

Oversized book pages/signs/item names are broadcast → client-side OOM/crash + log spam.

enforce title ≤32, ≤100 pages, page byte cap, and total component size on all broadcast paths (Set Container Content, Creative Slot included).

Invalid UTF-8 / chat JSON

Decoder exceptions or garbage components reaching other clients.

strict UTF-8 decode; validate component depth/size, click/hover events (no javascript: URLs).

Entity metadata type mismatch

Unknown type id or truncated value → client ArrayIndexOutOfBounds.

validate type id against the version table + terminator 0xFF present.

Chunk palette crash

Bad bits-per-block / palette size / light arrays crash the client.

server-side plugins rarely need this; proxy authors: validate palette bounds per version.

Brigadier / command crash

Malformed command node trees or absurd parse depth.

cap command length (32500/256) and Brigadier parse depth; strip unknown node types.

Invalid click/slot state

Stale state id or out-of-range slot → exceptions, dupes.

validate state id freshness and slot ∈ window + player inventory.

Packet rate flood

Animation/KeepAlive/teleport-confirm spam → CPU exhaustion (kick issue, not JVM crash).

per-connection token buckets per packet type; low caps pre-login (status/login).

NaN / teleport abuse

NaN positions, huge deltas, teleport-confirm flooding.

Float.isFinite() checks, delta caps, confirm-id matching.

Custom payload flood

32,767-byte payloads at high rate = bandwidth/CPU attack.

rate-limit plugin messages per channel; validate channel is a known/registered one pre-Play.

Handshake spoofing

\0-separated proxy data on direct connections; intent ≠ 1/2/3; hostname > 255.

reject \0 when not behind a proxy; whitelist intents; length checks.

Resource pack loop (1.17 era)

Server resends pack on decline → client stuck/loop.

cap resends per join; honor declined state per UUID.

Netty guard code (copy-paste)

Netty’s ByteBuf has no built-in VarInt — you implement it over readByte(). These snippets add the anticrash bounds the vanilla ones lack.

Safe VarInt / VarLong

public static int readVarInt(ByteBuf buf, int maxBytes) {   // 5 in-packet, 3 for length prefix
    int value = 0, bits = 0;
    while (true) {
        if (!buf.isReadable()) throw new DecoderException("VarInt truncated");
        byte b = buf.readByte();
        value |= (b & 0x7F) << bits;
        if ((b & 0x80) == 0) return value;          // note: does NOT reject overlong, add if wanted
        bits += 7;
        if (bits > maxBytes * 7 || bits > 32)
            throw new DecoderException("VarInt too big");
    }
}

public static void writeVarInt(ByteBuf buf, int value) {
    while (true) {
        if ((value & ~0x7F) == 0) { buf.writeByte(value); return; }
        buf.writeByte((value & 0x7F) | 0x80);
        value >>>= 7;
    }
}

Safe string & byte array (the OOM killer)

public static String readString(ByteBuf buf, int maxBytes) {
    int len = readVarInt(buf, 5);
    if (len < 0 || len > maxBytes) throw new DecoderException("String too long: " + len);
    if (len > buf.readableBytes()) throw new DecoderException("String length exceeds buffer");
    CharSequence s = buf.readCharSequence(len, StandardCharsets.UTF_8);
    if (s == null) throw new DecoderException("Bad UTF-8");
    return s.toString();
}

public static byte[] readByteArray(ByteBuf buf, int max) {
    int len = readVarInt(buf, 5);
    if (len < 0 || len > max) throw new DecoderException("Array too long: " + len);
    if (len > buf.readableBytes()) throw new DecoderException("Array length exceeds buffer"); // OOM guard
    byte[] out = new byte[len];
    buf.readBytes(out);
    return out;
}

Length-prefix + compression guard

// in your decoder, before reading a packet:
int length = readVarInt(in, 3);                       // length prefix ≤ 3 bytes
if (length > 2_097_152) throw new DecoderException("Packet too large");   // 0x200000
// if compression enabled:
int dataLength = readVarInt(in, 5);
if (dataLength > 2_097_152) throw new DecoderException("Badly compressed packet");
// inflate with a bounded output stream (e.g. Inflater with setLimit / counting wrapper)

Rate limiting sketch (per connection)

public boolean tryConsume(PacketType t) {             // token bucket per type
    long now = System.nanoTime(), refill = (long)((now - last) * ratePerSec / 1e9);
    tokens = Math.min(capacity, tokens + refill); last = now;
    if (tokens < 1) return false;                     // false → kick or skip handling
    tokens -= 1; return true;
}
