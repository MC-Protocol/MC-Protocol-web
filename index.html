Minecraft Protocol Values for Anticrash Development

A single-page reference of every wire-format constant, vanilla-enforced packet limit and known crash vector used when writing server-side validation (anticrash) for Minecraft Java Edition. Built from the Minecraft Wiki — Java Edition protocol/Packets (the wiki.vg merge), the Netty 4.0 ByteBuf javadoc, PrismarineJS minecraft-data, MCProtocolLib and ViaVersion sources.

⚠ Read this first: numbers marked wire are protocol constants; vanilla are enforced by the vanilla server/client (safe baselines for kicks); version-dep changed between releases — always re-check per protocol version in the links below; confirmed live was pulled directly from the wiki page for the current release during this update. These are defensive limits, not guaranteed constants.
The wiki.vg-merge protocol article on the Minecraft Wiki is published under CC BY‑SA 3.0, which explicitly permits building servers/clients/bots from it. Values below are reorganized and re-described for anticrash use rather than copied verbatim; consult the source page directly for the canonical field-by-field packet layouts.

Anticrash framing checks

Reject: length VarInt > 3 bytes · length > 2,097,151 · DataLength > 2,097,151 (clientbound) or > 8,388,608 (serverbound) · zlib output exceeding its declared size · packets arriving before Set Compression on a connection that already advertised one · unknown handshake intent ≠ 1/2/3.

VarInt & VarLong — full encoding reference

7 data bits per byte, MSB = continuation flag, least-significant group first (LEB128-style, but not Protocol Buffers varints — Minecraft's variant never uses ZigZag, so negative values always take the maximum byte count). VarInt caps at 5 bytes / 32 bits; VarLong caps at 10 bytes / 64 bits. Unnecessarily long encodings (e.g. 0x81 0x00 for 1) are legal but wasteful — many implementations reject them as non-canonical for defense-in-depth.

Teleport Flags & Light Data confirmed live

Teleport Flags (Int bit field)

Lower 8 bits: a set bit means that axis is relative to the entity's current value; unset means absolute.

Hex maskField
0x0001Relative X
0x0002Relative Y
0x0004Relative Z
0x0008Relative Yaw
0x0010Relative Pitch
0x0020Relative Velocity X
0x0040Relative Velocity Y
0x0080Relative Velocity Z
0x0100Rotate the velocity change according to the rotation change in the same packet, applied before the velocity change itself
Any bits set outside 0x01FF are undefined for this Int — mask and ignore, don't propagate unknown bits into physics code.

Slot:
  present: Boolean
  if present:

Position / Angle / UUID

// Position: 8-byte long, since 1.14 — X:26 | Z:26 | Y:12
long x = v >> 38;             // sign-extended automatically
long y = v << 52 >> 52;       // lowest 12 bits
long z = v << 26 >> 38;       // middle 26 bits

// Encoding direction:
// packed = ((x & 0x3FFFFFF) << 38) | ((z & 0x3FFFFFF) << 12) | (y & 0xFFF)

// Angle: 1 byte, 0..255 → 0..360° (step 1.40625)
float degrees = byteValue * (360f / 256f);

// UUID: two big-endian longs (MSB, LSB) — 16 bytes
UUID uuid = new UUID(buf.readLong(), buf.readLong());
Movement packets: vanilla clamps X/Z to ±29,999,984 (±3.0E7) and Y to ±2,031 on the client; the server should reject NaN/Infinity floats (Float.isFinite / Double.isFinite) and impossible deltas. Note the Position type's own field range (x/z ±33,554,431, y ±2,048) is wider than the movement clamp — validate against the tighter movement bound when checking player-originated coordinates, and against the Position type's bit-width bound when checking block-targeting fields (Query Block Entity Tag, Block Update, etc.).

Crash & exploit vectors

VarInt too big / overlong 🔴

5+ bytes for length prefix, or 32+ bits set.

length VarInt ≤ 3 bytes; in-packet VarInt ≤ 5 bytes / 32 bits; reject non-canonical (overlong) encodings.

Negative / huge array length 🔴

new byte[negative] → NegativeArraySizeException; new byte[huge] → OOM before reading.

check length ≥ 0 and length ≤ buf.readableBytes() (or a sane cap) before allocating.

Decompression bomb 💣

Tiny packet inflates to gigabytes → OOM/CPU burn.

cap uncompressed size at 2,097,151 (clientbound) / 8,388,608 (serverbound) like vanilla; cap compressed:uncompressed ratio and total inflate rate per connection.

Book ban 📚

Oversized book pages/signs/item names are broadcast → client-side OOM/crash + log spam.

enforce title ≤32, ≤100 pages, page byte cap, and total component size on all broadcast paths (Set Container Content, Creative Slot included).

Invalid UTF-8 / chat JSON

Decoder exceptions or garbage components reaching other clients.

strict UTF-8 decode; validate component depth/size, click/hover events (no javascript: URLs).

Entity metadata type mismatch

Unknown type id or truncated value → client ArrayIndexOutOfBounds.

validate type id against the version table + terminator 0xFF present.

Chunk palette crash

Bad bits-per-block / palette size / light arrays crash the client.

server-side plugins rarely need this; proxy authors: validate palette bounds per version, and that each light array is exactly 2048 bytes.

Brigadier / command crash

Malformed command node trees or absurd parse depth.

cap command length (32500/256) and Brigadier parse depth; strip unknown node types.

Invalid click/slot state

Stale state id or out-of-range slot → exceptions, dupes.

validate state id freshness and slot ∈ window + player inventory.

Packet rate flood

Animation/KeepAlive/teleport-confirm spam → CPU exhaustion (kick issue, not JVM crash).

per-connection token buckets per packet type; low caps pre-login (status/login).

NaN / teleport abuse

NaN positions, huge deltas, teleport-confirm flooding.

Float.isFinite() checks, delta caps, confirm-id matching.

Custom payload flood

32,767-byte payloads at high rate = bandwidth/CPU attack.

rate-limit plugin messages per channel; validate channel is a known/registered one pre-Play.

Handshake spoofing

\0-separated proxy data on direct connections; intent ≠ 1/2/3; hostname > 255.

reject \0 when not behind a proxy; whitelist intents; length checks.

Resource pack loop (1.17 era)

Server resends pack on decline → client stuck/loop.

cap resends per join; honor declined state per UUID.

Oversized Game Profile Properties

A resolvable profile or player-head item with a bloated Properties array is a cheap client-side amplification target.

enforce ≤16 properties, name ≤64, value ≤32,767, signature ≤1,024 on every profile-bearing packet, not just Login Success.

ID Set / ID or X type confusion

A Type/ID discriminator that doesn't match the branch actually present desyncs the parser mid-packet, corrupting every field that follows.

validate the discriminator value and that the following bytes match the branch it implies before trusting downstream fields.

Netty ByteBuf reference confirmed live

Netty's ByteBuf is the buffer type every Minecraft packet decoder is built on top of. It has no built-in VarInt/VarLong — those are layered on readByte() by the game itself — but it does give you the primitive index model, bounds-checked accessors, and reference counting that anticrash guard code leans on. Reference: Netty 4.0 ByteBuf javadoc.

The three-region buffer model

Every ByteBuf tracks two cursors, readerIndex and writerIndex, which always satisfy 0 ≤ readerIndex ≤ writerIndex ≤ capacity. Anything named read*/skip* consumes from readerIndex forward; anything named write* appends at writerIndex; anything named get*/set* is absolute-indexed and touches neither cursor.

0 readerIndex writerIndex capacity |-- discarded --|------ readable (content) ------|------ writable ------| (already ^ read*/skip* pulls ^ write* appends consumed) from here forward here forward
Reading past writerIndex or writing past capacity both throw IndexOutOfBoundsException rather than silently returning garbage — always let that exception propagate to a "truncated packet" kick instead of catching and continuing with a partially-read buffer.

Netty guard code (copy-paste)

Netty’s ByteBuf has no built-in VarInt — you implement it over readByte(). These snippets add the anticrash bounds the vanilla ones lack.

Safe VarInt / VarLong

public static int readVarInt(ByteBuf buf, int maxBytes) {   // 5 in-packet, 3 for length prefix
    int value = 0, bits = 0;
    while (true) {
        if (!buf.isReadable()) throw new DecoderException("VarInt truncated");
        byte b = buf.readByte();
        value |= (b & 0x7F) << bits;
        if ((b & 0x80) == 0) return value;          // note: does NOT reject overlong, add if wanted
        bits += 7;
        if (bits > maxBytes * 7 || bits > 32)
            throw new DecoderException("VarInt too big");
    }
}

public static void writeVarInt(ByteBuf buf, int value) {
    while (true) {
        if ((value & ~0x7F) == 0) { buf.writeByte(value); return; }
        buf.writeByte((value & 0x7F) | 0x80);
        value >>>= 7;
    }
}

Safe string & byte array (the OOM killer)

public static String readString(ByteBuf buf, int maxBytes) {
    int len = readVarInt(buf, 5);
    if (len < 0 || len > maxBytes) throw new DecoderException("String too long: " + len);
    if (len > buf.readableBytes()) throw new DecoderException("String length exceeds buffer");
    CharSequence s = buf.readCharSequence(len, StandardCharsets.UTF_8);
    if (s == null) throw new DecoderException("Bad UTF-8");
    return s.toString();
}

public static byte[] readByteArray(ByteBuf buf, int max) {
    int len = readVarInt(buf, 5);
    if (len < 0 || len > max) throw new DecoderException("Array too long: " + len);
    if (len > buf.readableBytes()) throw new DecoderException("Array length exceeds buffer"); // OOM guard
    byte[] out = new byte[len];
    buf.readBytes(out);
    return out;
}

Length-prefix + compression guard

// in your decoder, before reading a packet:
int length = readVarInt(in, 3);                       // length prefix ≤ 3 bytes
if (length > 2_097_151) throw new DecoderException("Packet too large");   // 2^21 - 1
// if compression enabled:
int dataLength = readVarInt(in, 5);
int cap = serverbound ? 8_388_608 : 2_097_151;          // 2^23 serverbound, 2^21-1 clientbound
if (dataLength > cap) throw new DecoderException("Badly compressed packet");

Rate limiting sketch (per connection)

public boolean tryConsume(PacketType t) {             // token bucket per type
    long now = System.nanoTime(), refill = (long)((now - last) * ratePerSec / 1e9);
    tokens = Math.min(capacity, tokens + refill); last = now;
    if (tokens < 1) return false;                     // false → kick or skip handling
    tokens -= 1; return true;
}
